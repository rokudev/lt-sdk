# LTCore: Benefits and Differentiators

## Overview

**LTCore** is the foundational library of the Roku LT Operating System — a single, self-contained interface that provides threading, memory, synchronization, I/O, library lifecycle, object management, time, interrupt control, low-power sleep, diagnostics, and structured logging. Every LT library interacts with the hardware and OS exclusively through LTCore, with no dependency on any external runtime, libc, or host OS interface. This design makes LTCore simultaneously the kernel interface, the standard library, and the runtime environment for all software running on LT.

---

## A Unified, ISR-Safe API Surface

The most immediate differentiator is coherence. FreeRTOS exposes kernel services as a collection of independent function families (`xTaskCreate`, `xQueueSend`, `vTaskDelay`, `pvPortMalloc`, etc.) with inconsistent naming conventions, mixed return types, and no common access model. Linux user-space programs call into `glibc`, `libpthread`, and the kernel through system calls that are never available from interrupt context.

LTCore presents a **single C struct of function pointers** — obtainable anywhere via `LT_GetCore()` — covering all system services. Every function that can be called from an interrupt service routine is explicitly annotated `LT_ISR_SAFE` in the interface definition, making ISR constraints visible at the call site rather than buried in documentation. This annotation is enforced at compile time, giving LT libraries a safety guarantee that neither FreeRTOS nor Linux can offer at the API level.

---

## Library Lifecycle Management

LT's dynamic library system is unique to either comparison platform. `OpenLibrary` and `CloseLibrary` load and unload named `.so` shared libraries at runtime on hosted platforms, or resolve pre-linked static libraries on embedded targets — using the same call in both cases. The `lt_openlibrary(LibraryName)` macro returns a typed pointer directly to the library's root interface, eliminating casts.

`SnapshotOpenLibraries` and `GetLibrarySnapshot` provide live introspection of every currently open library — its name, root interface name and version, and open count — without any external tooling. `EnumerateInstalledLibraries` lists everything available on the device. A `SetLibraryHook` mechanism allows any library to intercept open and close operations for substitution (dependency injection) or post-open patching, which is the basis for LT's built-in `MockObject`/`UnmockObject` unit-test facility. Neither FreeRTOS nor Linux provides an equivalent integrated library introspection and mock-substitution system.

---

## Object System with Reference Counting

LTCore mediates creation and destruction of all LT objects through `lt_createobject` / `lt_destroyobject` and their device and driver variants. Every object is reference-counted; `AddObjectRef` / `RemoveObjectRef` and `lt_destroyobject` are all equivalent to incrementing and decrementing the same count, and the object is released only when the count reaches zero. This model eliminates double-free errors and lifetime ambiguity in multi-threaded code without requiring garbage collection.

The `lt_createobject(Type, Specialization)` macro resolves the correct implementation class at runtime, allowing specialization to be changed — or mocked — without modifying caller code. FreeRTOS has no object system; Linux provides no equivalent for embedded or ISR-adjacent code.

## Heap Memory with Diagnostics

LTCore's `Alloc`, `ReAlloc`, and `Free` functions carry optional call-site annotation (file, line, thread) in debug builds. `EnumerateHeapAllocatedBlockInfo` walks every live heap block and reports its size, allocating thread, and call-site — a built-in memory-leak audit requiring no external profiler. `SnapshotMemstat` packs current, peak, and total heap utilization into a single 64-bit integer for efficient logging, and `FormatCanonicalMemstatString` renders it as a human-readable bracketed string.

Named memory regions (`GetNamedMemoryRegion`, `AllocFromRegion`) let BSP authors designate hardware-constrained regions such as DMA-only RAM; allocations from those regions are freed through the standard `Free` path using in-band headers. FreeRTOS supports heap regions but without call-site tracking or enumeration. Linux `malloc` offers neither named regions nor live enumeration without `valgrind` or a custom allocator.

## Structured Logging and Tracing

The `LTLOG` / `LTLOG_YELLOWALERT` / `LTLOG_REDALERT` macro family routes log entries through a section name, tag, severity, and format string. Logs can be directed to the console, to a server sink, or both. The `SetLogHookFunction` callback intercepts all log calls for queued deferred processing; LTCore automatically suppresses logs generated by the log-processing thread itself to prevent runaway recursion.

A separate low-overhead binary trace system (`Trace`, `TraceAddStreams`, `TraceSetStreamEnabled`) allows per-stream enable/disable at runtime without recompilation. `FormatCanonicalTimeString` renders any `LTTime` value as `[seconds.microseconds]` — from ISR context — enabling precise timestamped output without floating-point or heap allocation.

---

## Interrupt and Sleep Mode Control

`Disable` / `Enable` provide nestable interrupt disabling with a returned mask that must be passed back to the corresponding `Enable` call — preventing accidental unlock of an outer nest level. `SetInterruptVector` and `SetInterruptPriority` configure hardware interrupt routing through a portable abstraction with configurable priority levels.

The sleep mode subsystem is a differentiator with no direct FreeRTOS or Linux equivalent for embedded use. `SetEnterSleepModeProc` installs a BSP callback that LTCore invokes — in a reserved highest-priority thread — when the system has been idle for a configured delay. `DisallowSleepMode` / `ReallowSleepMode` issue and release numbered grants (up to 32) that prevent sleep entry during critical operations. `OnSleepAction` / `NoSleepAction` register event callbacks notified at going-to-sleep, sleep-aborted, and awakened-from-sleep transitions, with the ability to return a required wakeup time to LTCore.

---

## Handle System with Lifecycle Safety

LTCore's handle table manages all OS resources — threads, events, and library-defined handle types — through a uniform `LTHandle` (opaque integer). `IsHandleValid` queries handle liveness. `ReserveHandlePrivateData` / `ReleaseHandlePrivateData` provide a reference-counted mechanism that defers destruction of a handle until all reservations are released, preventing use-after-free when a handle is destroyed while another thread holds a pointer to its private data. `GetHandleStateString` returns a human-readable lifecycle state for debugging. `GetHandlesByInterface` and `GetHandlesByInterfaceName` enumerate all live handles of a given type — useful for diagnostics and test validation.

---

## Graceful Shutdown

`TerminateLT` initiates an orderly shutdown: all non-system threads receive terminate notifications, queued task procs are aborted, client-data release procs are called, and exit procs run before LTCore itself unwinds. `IsLTShuttingDown` allows subsystems such as health monitors to distinguish an intentional shutdown from an unexpected thread exit, preventing spurious reboots during a clean power-down sequence.

## Summary Comparison

| Capability | FreeRTOS | Linux (user space) | LTCore |
|---|---|---|---|
| Unified API access point | No — scattered functions | No — syscalls + glibc + pthreads | Yes — `LT_GetCore()` single struct |
| ISR-safe annotation enforced | No | N/A | Yes — `LT_ISR_SAFE` at compile time |
| Dynamic library lifecycle | No | `dlopen` / `dlclose` | `OpenLibrary` / `CloseLibrary` + typed macros |
| Live library introspection | No | No | `SnapshotOpenLibraries`, `GetLibrarySnapshot` |
| Integrated mock/substitute | No | No | `MockObject` / `UnmockObject` via library hook |
| Reference-counted objects | No | No | `lt_createobject` / `lt_destroyobject` |
| Call-site heap tracking | No | No (needs valgrind) | `EnumerateHeapAllocatedBlockInfo` |
| Named memory regions | Basic | No | `GetNamedMemoryRegion` / `AllocFromRegion` |
| Structured section+tag logging | No (printf-style) | syslog | `LTLOG` with severity, section, tag, sink routing |
| ISR-safe log output | No | No | `ConsolePrint` / `ConsoleStomp` (`LT_ISR_SAFE`) |
| Low-power sleep orchestration | Tickless idle (basic) | PM via kernel | Full callback + disallowance grant system |
| Handle lifecycle safety | No | No | Reserve/Release deferred destroy |
| Graceful shutdown | No | Signals + atexit | `TerminateLT` / `IsLTShuttingDown` |
| External dependencies | FreeRTOS kernel only | glibc, libpthread, kernel | None |

---

LTCore's design delivers the kernel services, runtime, and diagnostics infrastructure of a full OS in a self-contained interface small enough for a 64 KB embedded device, with the safety annotations, ISR compatibility, and introspection depth needed to build and debug production IoT firmware confidently.
